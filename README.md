# 🍽️ SmartServe

SmartServe is a web-based restaurant operations system. Guests open the menu from a table QR code and place orders, the kitchen prepares them, waitstaff serve them, and managers control menus, tables, and reporting.

**Live application:** [smart-serve-eta.vercel.app](https://smart-serve-eta.vercel.app)

> Administrative pages require authentication. Production usernames and passwords are intentionally not stored in this repository.

## How to use the application

### Guest

1. Scan the QR code at your table. Do not type the table URL manually: it contains a unique token, not just a table number.
2. Select **Add** next to the menu items you want.
3. Open the cart and adjust quantities and serving courses if necessary.
4. Check the table number and total, then place the order.

A valid guest URL looks like this:

```text
https://smart-serve-eta.vercel.app/<restaurant-slug>/table/<table-qr-token>
```

A URL such as `/smart-bistro/table/1` will not work. The final segment must be the secure QR token generated by SmartServe.

### Owner or administrator

1. Open the [sign-in page](https://smart-serve-eta.vercel.app/login).
2. After signing in, open **Restaurant management** and select the active restaurant. Every operational dashboard is scoped to that selection.
3. Use the quick links:
   - **Manager dashboard** — active orders, menu editor, tables, and statistics;
   - **QR code generator** — menu links and ready-to-use table QR codes;
   - **Owner dashboard** — sales and operational overview;
   - **Kitchen** and **Waiter** — staff workspaces.
4. Create tables before opening the QR code generator. Select each table and print or save its generated QR code.

### Kitchen

1. Sign in with an account that has access to the restaurant.
2. Open **Kitchen** from Restaurant management.
3. Start pending items and mark them ready when preparation is complete.

The board refreshes automatically. Polling is the reliable update path, so a new order may take a few seconds to appear.

### Waiter

1. Sign in and open **Waiter** for the active restaurant.
2. Track ready orders, confirm that items were served, and close the bill after service.

## Quick local setup

Requirements: Node.js 20+ and PostgreSQL.

```bash
git clone git@github.com:MykhailoLoniak/SmartServe.git
cd SmartServe
npm ci
cp .env.example .env
```

Set at least `DATABASE_URL`, `DIRECT_URL`, and `NEXT_PUBLIC_APP_URL` in `.env`, then run:

```bash
npm run prisma:generate
npm run prisma:migrate:dev
npm run prisma:seed
npm run dev
```

Open [http://localhost:3000](http://localhost:3000). The local seed creates two demo restaurants. Sign-in credentials come from `SEED_ADMIN_EMAIL` and `SEED_ADMIN_PASSWORD` in your `.env` file.

> `prisma:seed` is for development only. To bootstrap a production demo once, use the guarded `npm run bootstrap:demo` flow described in [docs/deployment.md](docs/deployment.md).

## Routes

| Scenario | Route |
| --- | --- |
| Sign in | `/login` |
| Select a restaurant | `/admin/restaurants` |
| Manager dashboard | `/<restaurant-slug>/admin/dashboard` |
| Table QR codes | `/<restaurant-slug>/admin/qr` |
| Owner dashboard | `/<restaurant-slug>/admin/owner` |
| Kitchen | `/<restaurant-slug>/staff/kitchen` |
| Waiter | `/<restaurant-slug>/staff/waiter` |
| Guest menu | `/<restaurant-slug>/table/<table-qr-token>` |
| Application health | `/api/health` |
| Application and database readiness | `/api/ready` |

Route access depends on the user's role and restaurant membership.

## Technology

Next.js 15 · React 19 · TypeScript · Tailwind CSS 4 · Prisma · PostgreSQL · Zustand · session-based authentication · polling with optional Supabase Realtime.

SmartServe is multi-tenant: one deployment supports multiple restaurants, while the server checks access separately for each restaurant.
